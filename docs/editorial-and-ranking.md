# Методика и редакционная архитектура — проект v1

Область первого этапа: только главная. Данные компаний, реальный ИИ-конвейер, рейтинг, заявки, статьи и биллинг не реализованы.

## Оценка
Весовые группы: реализованные работы 25%; репутация 20%; прозрачность условий 20%; сроки и процесс 15%; гарантии и поддержка 10%; открытость компании 10%.

Каждый критерий 0–5. До запуска нужны отдельные предметные шкалы для студий, кухонь, мебели, окон и дверей. Ноль выставляется только при подтверждённых основаниях, не из-за отсутствия данных. Неизвестное — null. Итог не публикуется до покрытия не менее 80% веса и всех обязательных для категории критериев. Неизвестные веса не перенормируются автоматически; правила допуска должны быть утверждены до первого выпуска.

Источники: URL, дата доступа, дата события, цитата/наблюдение, тип (заявление компании, документ, независимая публикация, отзыв), уверенность, подтверждение происхождения. Дубликаты и перепечатки — один источник. Количество рекламы/публикаций не является качеством. Негативный отзыв сам по себе не доказывает нарушение.

ИИ извлекает факты со ссылками и оценивает их по рубрике; воспроизводимый алгоритм рассчитывает итоговый балл. Сохранять версию модели/промпта/критериев, историю пересчётов и основания. Ошибки и спорные сведения направлять на проверку до публикации; итоговое место формируется алгоритмом. Равные баллы — равные места или заранее опубликованный tie-break по полноте данных. Новые материалы можно подать бесплатно, после верификации — пересчёт.

## Промо
Отдельная сущность Placement, не поле органического score. До 3 активных компаний перед рейтингом. Порядок промо коммерческий. Одна компания может иметь placement и organic entry. Для каждой вставки: формат, компания, контекст/город, период, приоритет, пометка, рекламодатель, необходимые сведения о рекламе. До активации конкретного размещения проверять действующие требования к маркировке. Карточки других городов не должны маскировать географию рекламодателя. Исходящие платные ссылки rel=sponsored.

## Архитектура следующего этапа
- /ratings/{category}/{city}/ — исследованный рейтинг, методика, дата и ссылки на источники.
- /companies/{slug}/ — описание, контакты, регион, доказательства оценки, история изменений.
- /journal/{slug}/ — статья.
- /authors/{slug}/ — реальный автор/эксперт, опыт, роль, публикации.
- /methodology/, /about/, /advertising/, /corrections/.

Не генерировать массовые пустые страницы городов. Только индексируемые полезные страницы в sitemap. Фильтры не создавать как бесконечные индексируемые комбинации.

## Статьи
Редакция — автор/организация; реальный дизайнер или собственник производства — соавтор либо эксперт с точно указанным вкладом и согласием. Не придумывать имена и экспертизу. Видимые дата публикации/обновления, биография, источники, оригинальные выводы, практические примеры. Партнёрские материалы заметно отмечать. Article/BlogPosting JSON-LD должен совпадать с видимым авторством. Не ставить AggregateRating на основе нашего собственного редакционного score.

## SEO
Статический HTML, один H1, логичные H2/H3, canonical, метаданные, Organization/WebSite/AboutPage. Сейчас noindex для черновика. После запуска — self-canonical, sitemap, реальные 404, региональная релевантность, внутренняя перелинковка, локальные шрифты, WebP/srcset, LCP/INP/CLS измерения. Нельзя обещать позиции или цитирование нейросетями. Для цитирования нужны краткие проверяемые выводы, авторство, даты и ссылки на первичные источники.
